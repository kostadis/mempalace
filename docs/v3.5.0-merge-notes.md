## NEW divergence sites discovered (not in `divergence.md`)

### §8 — Pluggable backend layer collision  ⚠️ HARD CONFLICT · DECISION REQUIRED

Both branches independently built a pluggable backend layer on top of the shared v3.3.5 `backends/{base,chroma}.py`, and they are **incompatible**:

- **Upstream v3.5.0** `backends/`: `base.py`, `chroma.py`, `registry.py`, `pgvector.py`, `qdrant.py`, `sqlite_exact.py`, `embedding_wrapper.py`, `_sidecar.py`, `__init__.py`. Framework introduced in **v3.4.0** (`ed77125` sidecar/qdrant identity, `ec5d1eb` pgvector + registry — RFC 001, #1730).
- **Local**: `base.py`, `chroma.py`, `registry.py`, **`turbovec.py`**, `__init__.py` (turbovec adapter + `MEMPALACE_BACKEND` routing).

Overlapping filenames → **add/add** conflict on `registry.py`, **modify/modify** on `base.py` / `chroma.py` / `__init__.py`. `git diff v3.5.0 HEAD` on these three files shows local **−1,299 lines** (local slimmed `chroma.py` by ~1,078 and `base.py` by ~316 vs upstream v3.5.0).

**The standing "keep local design" rule is WRONG here.** Keeping local `base.py`/`registry.py` would (a) discard upstream's pgvector/qdrant/sqlite_exact backends and (b) break them, since they depend on upstream's evolved base interface. The correct resolution is to **take upstream's backend framework and re-home `turbovec` + `MEMPALACE_BACKEND` routing onto it** — a scope/architecture decision that needs an explicit user checkpoint before the merge that introduces it (sub-issue **C / v3.4.0**), per the project's "LLMs are renderers, not architects" rule.

### §9 — Cursor integration duplication  (semantic dup, NOT a hard git conflict)

Both branches independently added Cursor support, on **different paths** (so they coexist rather than git-conflict):

- **Upstream v3.4.1**: `hooks/cursor/*` (7 files, bash + `lib/common.sh`) + `.cursor-plugin/`.
- **Local**: `hooks/mempal_cursor_*.sh` (4 scripts) + `cursor` harness inside `mempalace/hooks_cli.py`.

No merge conflict, but a **design-philosophy clash** (upstream bash hooks vs local Python `hooks_cli` harness) and duplicated surface. Decide post-merge whether to keep both, retire local in favor of upstream, or fold upstream's into the Python harness. Does not block the merge; flag for sub-issue F.

## Revised risk assessment

- This is a **much larger and riskier** merge than v3.3.5. The per-release decomposition (B–E) still holds, but B (v3.3.6, 227 commits) is **not** small, and C (v3.4.0) carries the backend-framework architecture decision.
